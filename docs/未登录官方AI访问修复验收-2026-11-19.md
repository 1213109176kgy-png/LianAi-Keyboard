# 安卓未登录官方 AI 访问修复

## 行为

官方 AI 获取凭据时，必须同时存在非空 token 和可解析的用户资料，用户 ID 和手机号均不能为空。个人中心和 AI 请求通过同一会话读取逻辑判断身份；仅残留 token、用户记录缺失、JSON 损坏、加密记录无法解密、空账号字段均视为未登录，不提供官方请求凭据。

登录保存先验证完整性并构造用户记录，再撤销旧 token、保存用户资料，最后发布新 token。读取与保存使用会话锁，避免不同会话存储实例读到写入过程中的半份信息。退出登录先移除 token。

文字回复、超会说、截图识别及官方语音均使用 `UserSessionStore.token()`，覆盖此检查。现有服务端 VIP、业务模型开关和失效 token 校验不变；官方语音仍按原规则要求登录，不增加 VIP 限制。

自配模型路由保持原样；退出登录不清除文字、视觉、语音的自配 API Key。

## 测试

JDK 17 / Gradle 8.10.2。单元测试和标准 Debug APK 构建通过。

单元测试共 74 项，0 失败、0 错误、0 跳过，新增 `UserSessionStoreTest` 六项：

- 残留 token 与多种缺失、损坏或字段无效的用户记录均不能认证。
- 正常登录、跨实例读取和退出保持一致。
- 缺失或空 token 时，界面和凭据都按未登录处理。
- 用户资料写入失败后不能发布新凭据，也不能沿用已撤销的旧凭据。
- 无效登录响应不会替换原有完整登录态。
- 即使传入缓存 VIP 配置，未登录也不能选择任何官方文字/视觉业务；完整的自配模型仍可选用。

Android 14 / `lianai_test` 模拟器集成测试共 4 项通过，使用独立的 `com.lianai.keyboard.touchtest` 包与隔离偏好目录，没有覆盖正式 App 的账号和模型设置：

- `SessionAccessRegressionTest` 三项：真实 Android Keystore 加解密、孤立 token、损坏 JSON 和密文；真实登录/退出及自配密钥保留；生产路由拒绝匿名官方业务、保留自配路由，官方语音在发送请求前拒绝匿名会话。
- `KeyboardTouchRegressionTest#slightDriftPastPaintedEdgeStillTypesInNormalAndPasswordEditors`：真实按键触摸事件在普通编辑器和密码编辑器中均通过。

未连接安卓真机，本轮没有宣称真实手机验收。测试没有调用真实 AI 服务或读取用户凭据。代码提交沿用上述单元测试、模拟器集成测试及构建结果，安卓真机验收仍未完成。
